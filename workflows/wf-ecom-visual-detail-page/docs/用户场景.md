## 场景一 · 电商 AI 商品视觉的日常用法

- **角色**：电商 AI 商品视觉
- **触发时机**：需要「详情页排版生成」这件事有结果的时候
- **他会说**：`用 wf-ecom-visual-detail-page 帮我详情页排版生成`
- **需要准备**：流程起始材料（见执行步骤第 1 步）；用户身份与目标渠道/平台
- **拿到什么**：详情页排版生成交付物（按执行步骤逐步产出）
- **容易踩的坑**：文字过多是详情页通病，优先级是'少而准'

## 场景二 · 换成你自己的材料

同一句话，把材料换成你手头的真实数据即可：

```text
用 wf-ecom-visual-detail-page 处理下面这份材料：
<粘贴你的内容 / 贴文件路径>
```

**输入结构不要改**：字段名变了，脚本会读不到；缺字段时应当被明确告知缺什么，而不是猜。

| 字段 | 必填 | 说明 |
|---|---|---|
| 流程起始材料（见执行步骤第 1 步） | ✅ | 缺失会导致输出不可用 |
| 用户身份与目标渠道/平台 | ✅ | 缺失会导致输出不可用 |
| 历史产出 | ⬜ | 有则更好 |
| 账号人设 | ⬜ | 有则更好 |
| 渠道规则 | ⬜ | 有则更好 |
| 上一周期数据 | ⬜ | 有则更好 |

## 场景三 · 边界情况（重要）

这几条写清楚做不到什么，比列一堆能力更有用：

- 只负责本工作流这一条链路，不承担所属员工的其它职责
- 步骤与原子技能是**指示性映射**，允许按实际情况调整，不是强制编排
- 中途缺料必须停下来问，不允许用假设补齐
- 本工作流共 3 步，**中途缺料要停下来问**，不要用假设把链路填满——填出来的结果是废的
