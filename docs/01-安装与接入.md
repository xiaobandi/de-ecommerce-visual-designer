# 01 · 安装与接入

## 1. 前置

- Python ≥ 3.9（仅测试脚本需要，运行技能本身不需要）
- 一个支持文件读取的 Agent 运行环境（WorkBuddy / ChatGPT / DeepSeek Harness /
  Kimi Work / 豆包工作任一）
- 可选：按 `connectors/bindings.yaml` 注入连接器凭证（环境变量）

## 2. 五平台安装（各自的路径，不是一张总表）

> **技能单元 = 一个含 `SKILL.md` 的目录**。目录名必须与 `SKILL.md` 里 `name` **逐字相同**——
> 不一致会**静默不加载且不报错**，这是跨平台失败率最高的一条（见 `docs/05-验收与测试.md` 的 structure 套件）。

### 2.1 取内容与自检（所有平台通用）

```bash
git clone <本仓库地址> && cd de-ecommerce-visual-designer
pip install pyyaml
python3 tests/run.py            # 先跑一遍自检，确认结构、契约、文档、脚本都对得上
```

### 2.2 WorkBuddy

```bash
# 用户级：跨所有项目可用
cp -r skills/<技能名> ~/.workbuddy/skills/
cp -r workflows/<工作流名> ~/.workbuddy/skills/

# 项目级：随仓库共享给团队
cp -r skills/<技能名> <工作区>/.workbuddy/skills/
```

触发：`description` 命中即自动匹配，或直接提及技能名。

### 2.3 跨客户端共享约定（`npx skills add` 与多数新客户端）

```bash
npx skills add <owner>/de-ecommerce-visual-designer                 # 无需任何 manifest，有 SKILL.md 即可

# 或手工放置（项目级覆盖用户级）
cp -r skills/<技能名> <项目>/.agents/skills/
cp -r skills/<技能名> ~/.agents/skills/
```

### 2.4 ChatGPT

侧边栏 → **Plugins** → 顶部切到 **Skills** 标签（**没有独立的 Skills 菜单**，最容易找不到），
上传技能包；调用用 `@<skill-name>` 显式点名。
⚠️ 截至记录，仅 Business / Enterprise / Healthcare / Edu 工作区可用，Free / Plus / Pro 不可用。

### 2.5 DeepSeek Harness（dsh）

```bash
npx @deepseek-ai/dsh
dsh --profile web --dump-config     # 打印实际插件图，排查挂载问题
```

会话日志可回放、fork、全文检索——技能行为异常时来这里回放最快。
沙箱 fail-closed，**写文件失败是沙箱拦截不是技能问题**，走降级路径。

### 2.6 Kimi Work

插件市集安装，新会话输入 `/` 调出。
⚠️ **官方明确：装了不等于每轮自动调用，需要时手动选**——所以本员工的技能都写足了触发词。

### 2.7 豆包工作

左侧菜单「**技能 · 连接器 · 伙伴**」→ 右上角 `+` → 上传技能包。
一行装 GitHub 包：`新建技能 安装:https://github.com/<user>/de-ecommerce-visual-designer`
触发在**工作流输入框**，**不是聊天窗口的斜杠命令**。

## 3. 挂载公共依赖（所有平台都要做）

本员工依赖 `agent-skills-core@1.0.0`：

```bash
git clone <core 仓库地址> agent-skills-core
# 把 agent-skills-core/skills 一并挂到与上一步相同的位置
```

`dependencies.yaml` 里列出了用到的每个公共技能与版本。**不要**把这些技能
复制进本仓库——复制会产生多份副本，之后各自漂移。

## 4. 装完必须验的两条触发路径（装了不触发＝没装）

1. **关键词触发**：说一句自然会说的话，例如
   `人工`
2. **显式点名**（跨平台最稳的一条）：

```text
用「平台规格适配」处理这份材料：<材料>
```

两条都试过还不动，按 §6 排查。

## 5. 灌知识库

1. 按 `kb/schema.yaml` 的 `collections` 采集语料，落到 `kb/corpus/<collection>/`
2. 入库前按 `pii_policy` 脱敏
3. 向量化参数用 `embedding` 段；检索参数用 `retrieval` 段
4. 灌完跑一次 `tests/run.py --suite contract` 验证引用可解析

## 6. 常见问题

| 现象 | 原因 | 处置 |
|---|---|---|
| 技能装了但**完全没反应、也没报错** | 目录名与 frontmatter `name` 不一致，或挂错层级 | 二者必须逐字相同；确认挂的是含 `SKILL.md` 的**整个目录** |
| Kimi Work 里不自动调用 | 该平台明确不自动调用 | 用 `/` 手动选，或走显式点名 |
| 豆包加了技能不生效 | 在聊天窗口用了斜杠命令 | 触发入口是**工作流输入框** |
| ChatGPT 找不到 Skills | 找的是独立菜单 | 走 Plugins → Skills 标签；并确认工作区版本 |
| 写文件报错 | dsh 沙箱 fail-closed | 走「环境探测与降级」的降级路径 |
| 检索总是「无匹配」 | `min_score` 过高或语料未灌 | 先把 `min_score` 降到 0.2 验证连通性 |
| 连接器报未绑定 | `bindings.yaml` 仍是 `unbound` | 注入对应环境变量并把 status 改为 `bound` |
